## 目标 1：健壮的 RAG 知识库加载

### 需求描述
确保 `knowledge_node.py` 能够真正读取本地知识库文件，完成正确的向量化处理，拒绝任何形式的空占位符实现。

### 验收标准

- [ ] **文件读取能力**
  - 支持读取 `.txt` 和 `.md` 格式的本地文件
  - 能够递归读取指定目录下的所有知识库文件
  - 文件编码自动检测（UTF-8 / GBK 等）

- [ ] **向量化正确性**
  - 使用智谱 AI 的 `embedding-2` 模型进行文本向量化
  - 向量维度与模型输出一致（1024 维）
  - 向量库持久化到本地，避免重复计算

- [ ] **健壮性保障**
  - 知识库文件缺失时给出明确错误提示，而非静默失败
  - 空文件或无效文件自动跳过并记录警告日志
  - 支持知识库热更新（文件变更后自动重新加载）

### 关键代码检查点
```python
# 必须验证的要点
1. from langchain_text_splitters import RecursiveCharacterTextSplitter
2. embedding_model = ZhipuAIEmbeddings(model="embedding-2")
3. 确保 VectorStore 不是空集合或占位符
```

## 目标 2：顺滑的 LangGraph 状态流转

### 需求描述
在各个 Node 节点（特别是意图提取和生成回复）之间，确保传递的 State 是纯净、完整、可预期的字典结构。针对缺失参数的分支，采用**优雅降级**策略而非中断抛错。

### 验收标准

- [ ] **State 纯净性**
  - 所有 Node 输入/输出均为标准的 Python 字典
  - State 中不允许包含未序列化的对象或私有属性
  - 状态流转日志清晰可追踪

- [ ] **缺失参数处理**
  - 当缺少客户姓名时，使用默认值 `"尊敬的客户"`
  - 当缺少价格信息时，使用默认值 `99999` 并标记为"待确认"
  - 所有默认值必须在日志中明确记录

- [ ] **流程完整性**
  - 无论用户输入是否完整，流程必须**一气呵成**走到最后一个节点
  - 禁止在 Node 内部抛出未捕获异常导致流程中断
  - 最终节点必须生成完整的回复话术和文档列表

### 状态流转示意图
```
用户输入 → 意图识别 → 参数提取 → [参数补全] → 知识检索 → 回复生成 → Excel生成
                ↓              ↓                      ↑
           强制JSON解析    缺失参数填充默认值      兜底回复保障
```

## 目标 3：完美的文档生成闭环 (Excel)

### 需求描述
在 `document_nodes.py` 中，使用 `openpyxl` 库接收来自上游节点的结构化数据，生成格式规范、计算准确的 Excel 报价单文件。

### 验收标准

- [ ] **数据完整性**
  - Excel 中包含真实的产品名称（来自知识库或参数提取）
  - 包含单价、数量、小计金额
  - 包含总价自动计算（`SUM` 公式或程序计算）

- [ ] **格式规范性**
  - 表头加粗、居中对齐
  - 金额列使用货币格式（¥XX,XXX.00）
  - 列宽自适应内容
  - 添加边框和适当的背景色

- [ ] **文件管理**
  - 生成的文件保存到 `output/` 目录
  - 文件名包含时间戳和业务标识（如 `报价单_20250306_143022.xlsx`）
  - 文件生成成功后返回完整的文件路径和文件名

### Excel 模板结构
| 序号 | 产品名称 | 单价（元） | 数量 | 小计（元） |
|:----:|:---------|:----------:|:----:|:----------:|
| 1 | {产品A} | 10,000 | 2 | 20,000 |
| 2 | {产品B} | 5,000 | 3 | 15,000 |
| **合计** | - | - | - | **35,000** |

## 目标 4：前后端接口对齐

### 需求描述
建立标准、一致、健壮的文档下载交互流程，确保前端能够正确渲染下载按钮，用户点击后能够成功获取生成的文件。

### 验收标准

#### 后端接口规范

- [ ] **响应格式**
  ```json
  {
    "reply": "这是给客户的回复话术... 生成的文件：报价单_20250306_143022.xlsx",
    "documents": [
      {
        "filename": "报价单_20250306_143022.xlsx",
        "path": "/output/报价单_20250306_143022.xlsx"
      }
    ]
  }
  ```

- [ ] **文件名传递**
  - 完整的文件名必须追加到 `reply` 字符串末尾
  - `documents` 列表必须包含所有生成的文件信息
  - 文件名支持中英文混合，无乱码

- [ ] **下载 API**
  - 提供 `/api/download/{filename}` 端点
  - 支持中文文件名正确解码
  - 文件不存在时返回 404 和友好提示

#### 前端交互规范

- [ ] **数据解析**
  - 使用支持中文的正则提取文件名：`/[\w\-\u4e00-\u9fa5]+\.\w+/g`
  - 对 `reply` 和 `documents` 进行防御性空值检查
  - 对提取的文件名列表进行去重处理

- [ ] **UI 渲染**
  - 渲染极具科技感的【📥 下载表格】按钮
  - 按钮样式统一、响应式适配
  - 下载过程中显示加载状态

- [ ] **下载调用**
  - 点击按钮调用后端下载 API
  - 处理下载成功/失败的反馈提示
  - 支持多文件批量下载
